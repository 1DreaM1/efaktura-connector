Graf toku API requestov

Čítanie ≈ 19 min5 sekciíUpravené 27. 11. 2026

Táto stránka zobrazuje všetky vzdialené vetvy requestov konektora: SAPI, Peppol Gateway, Integrator API, PDS a získanie SAPI OAuth tokenu. Lokálne UBL čítanie, zápis a validácia cez API request neposielajú.

SAPI aj Peppol Gateway používajú rovnaký SAPI OAuth token. Bežné Integrator API requesty používajú X-Integrator-Token; nejde o token získavaný cez SAPI OAuth.

PDS submission patrí do Integrator API, ale autentifikuje sa podpisom X-PDS-Secret vypočítaným nad už zakódovaným JSON telom. Každá vetva používa spoločné ApiRequest a ApiConnector; líši sa autentifikačným senderom a transportom.

SAPI vetva pokrýva token, odoslanie a príjem dokumentov aj stav tokenu. Gateway vetva pokrýva discovery, kontrolu a odoslanie dokumentov, stav doručenia a správu webhookov. Odpovede 401 obnovuje AuthenticatedRequestSender najviac raz; toto obnovenie je oddelené od HTTP retry.

V nasledujúcich tabuľkách hlavičky uvádzajú autentifikáciu aj hlavičky špecifické pre operáciu. Transport automaticky pridáva Content-Type: application/json pri JSON tele; Accept je predvolene application/json.

Výnimkou je XML obsah MLS, pri ktorom endpoint nastaví Accept: application/xml. — znamená, že query alebo body nie sú definované. Request body, ktorý je uvedený, je podľa OpenAPI povinný; povinnosť jednotlivých polí sa riadi schémou.

Odpoveď uvádza úspešný HTTP status a PHP návratový typ; ak sa názov líši, nasleduje aj OpenAPI schéma.

Bežná vetva zahŕňa správu OAuth klientov, prístupov participantov, aktiváciu, participant list a súhrny dokumentov. PDS vetva odosiela subjecty cez POST /v1/integrators/{integratorId}/pds/subjects.

Obe vetvy zdieľajú ProviderTransport a executor stack, no každý request dostane iba autentifikáciu zodpovedajúcu svojej vetve.

Ukážkové requesty a odpovede¶[upraviť zdroj]

Ukážky používajú vymyslené identifikátory. JSON request zobrazuje iba telo; metódu, cestu, query a hlavičky uvádza tabuľka endpointov. Hodnota XML v ukážkach je skrátená. Tokeny, secrets a overovacie údaje sú zástupné.

Chybové ukážky používajú OpenAPI error envelope: SAPI/Gateway vracia SapiErrorResponseEnvelope, Integrator API IntegratorSapiErrorResponseEnvelope s rovnakým tvarom. HTTP status je uvedený mimo JSON.

Kódy, správy a korelačné ID sú ukážkové; pole retryable je odporúčanie poskytovateľa a nemení retry bezpečnosť operácie v konektore.

Spoločné vykonanie a odpoveď¶[upraviť zdroj]

flowchart LR
    Request[ApiRequest] --> Connector[ApiConnector vytvorí HttpExchangeRequest]
    Connector --> Auth[Príslušný autentifikačný sender]
    Auth --> Transport[Transport pridá base URL a scope]
    Transport --> BP[Backpressure a voliteľný request lock]
    BP --> CB[Circuit breaker]
    CB --> Retry[Retry podľa bezpečnosti requestu]
    Retry --> Log[Voliteľné logovanie]
    Log --> Metrics[Voliteľné metriky]
    Metrics --> Curl[cURL: HTTPS, TLS, limit odpovede]
    Curl --> Provider[SAPI / Gateway / Integrator API]
    Provider --> Curl --> Exchange[HttpExchangeResult]
    Exchange --> Status{HTTP 2xx?}
    Status -->|nie| Error[ProviderErrorResponseException]
    Status -->|áno: JSON| Json[JSON dekódovanie a endpoint mapper]
    Status -->|áno: XML| XML[Bezpečné XML parsovanie]
    Status -->|áno: telo netreba| Done[Úspešné dokončenie]
    Json --> Model[Factory alebo Mapper: Core model]
    XML --> Body[Pôvodné XML bajty]
    Model --> Core[Endpoint vráti Core model; adaptér ho odovzdá]
    Body --> Core
    Done --> Core
    Error --> Caller[Hostiteľ dostane technickú výnimku]
    Core --> Caller

GET je štandardne bezpečný na retry. Ostatné operácie sa opakujú iba po výslovnom označení endpointom ako bezpečné. SAPI OAuth token request je označený ako retry-safe; odoslanie dokumentu automatický retry nemá.

Odpoveď mimo 2xx sa prevedie na technickú výnimku a pri neplatnom JSON, XML alebo tvare dát vznikne InvalidProviderResponseException.

Podrobnosti o endpointoch a HTTP metódach sú v prehľade API, o autentifikácii a retry v transporte a autentifikácii a o zodpovednostiach klientov v toku dát a triedach.
