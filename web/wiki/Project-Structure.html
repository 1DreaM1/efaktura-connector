Štruktúra balíka a hranice modulov

Čítanie ≈ 8 min5 sekciíUpravené 27. 11. 2026

Repozitár obsahuje samostatné PHP jadro, voliteľný Laravel bridge, lokálne validačné zdroje, testy a dokumentáciu. Jadro nepozná hostiteľský workflow ani jeho perzistenciu; rozhrania v Core umožňujú aplikácii používať alebo nahradiť implementácie z Infrastructure.

Composer mapuje prefix DreaM1\EfakturaConnector\ na src/; napríklad DreaM1\EfakturaConnector\Core\Contracts\ zodpovedá src/Core/Contracts/. Voliteľný prefix DreaM1\EfakturaConnector\Laravel\ mapuje na integrations/laravel/src/.

Verejné Core typy používajú namespace DreaM1\EfakturaConnector\Core\....

Domain\EFaktura\Webhooks\WebhookIdentifier je nemenný hodnotový objekt, ktorý odmieta prázdne ID webhooku a vracia pôvodný reťazec cez value().

Infrastructure\Ubl\UblDocumentType centralizuje štrukturálne rozdiely medzi UBL Invoice a CreditNote, ktoré používajú načítanie XML, čítačka, zapisovač a XSD validátor.

Infrastructure\ResourcePath skladá cesty k pribaleným číselníkom a validačným zdrojom so separátormi aktuálneho operačného systému.

Predvolená samostatná transportná skladba používa in-memory backpressure a circuit breaker, ktorých stav sa nezdieľa medzi PHP workermi.

Predvolený backpressure wrapper však cez FileHttpRequestExecutionLock sériovo vykonáva HTTP requesty medzi procesmi s rovnakou kanonickou cestou aplikácie a OS používateľom.

Laravel bridge používa Laravel Cache pre backpressure a circuit breaker a predvolene aj pre HTTP request lock cez Cache::lock(), spolu so zámkom obnovy OAuth tokenu. Ak Laravel alebo cache store lock API neposkytuje, bridge použije lokálne súborové zámky.

Pri driver=file sa namiesto cache používa FileHttpRequestExecutionLock s koreňom v basePath(). Zdieľaná cache koordinácia vyžaduje podporu atómových zámkov; súborový lock sa nezdieľa medzi OS používateľmi ani hostmi.

Core a Domain nevolajú HTTP ani Laravel. Infrastructure implementuje porty a mapuje provider API do modelov konektora. Laravel bridge skladá tieto implementácie do kontajnera; pri použití bez Laravelu ich aplikácia zostaví sama.

Tok požiadavky a lokálne UBL operácie¶[upraviť zdroj]

Pri vzdialenej operácii aplikačný port alebo provider adaptér zavolá endpoint. Endpoint zostaví ApiRequest, ApiConnector spracuje HTTP odpoveď a endpoint alebo adaptér ju prevedie na typovaný výsledok.

flowchart LR
    Host[Hostiteľský workflow] --> Port[Core kontrakt]
    Port --> Adapter[Infrastructure provider/gateway]
    Adapter --> Endpoint[SAPI alebo Peppol endpoint]
    Endpoint --> Connector[ApiConnector]
    Connector --> Auth[AuthenticatedRequestSender]
    Auth --> Transport[Transport a executor]
    Transport --> Provider[Poskytovateľ]

UBL čítanie a zápis sú lokálne operácie bez HTTP. UblXmlDocumentLoader bezpečne načíta XML, UblDocumentReader vytvorí doménové hodnoty a UblDocumentWriter serializuje draft na XML.

Validátory sú samostatné služby, takže samotné čítanie automaticky nespúšťa XSD ani Peppol kontroly.

Testy a dokumentácia¶[upraviť zdroj]

  • tests/Unit/ overuje hodnoty, mapovanie odpovedí, endpointy a jednotlivé infraštruktúrne komponenty; testy Core UBL validácie a XML sú v samostatných podadresároch a transportné testy sú pri API testoch.
  • tests/Integration/ používa pripravené odpovede a fake transport na overenie celých tokov bez volania produkčného poskytovateľa.
  • tests/Architecture/ chráni hranice balíka a jeho závislostí.
  • Zmeny verejných endpointov aktualizujú API referenciu; zmeny konfigurácie aktualizujú stránku Konfigurácia; zmeny validačných artefaktov aktualizujú resources/validation/README.md.

Poskytovateľský API kontrakt je v docs/eFaktura/api/openapi.json. Prehľad zodpovedností a hlavných tokov je v architektúre a tokoch.
