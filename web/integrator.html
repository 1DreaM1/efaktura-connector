Správa integrátora

Od registrácie klienta po prístup účastníka.

Integrator API slúži na správu OAuth klientov a ich účastníkov. Je to samostatná administratívna vrstva: vydaný klientsky secret sa používa pri neskoršom získaní OAuth tokenu pre SAPI a Peppol Gateway.

AutorizáciaTypický procesMetódy
Samostatný klient a prístup

Jeden integrátor. Viac klientov a účastníkov.

Hostiteľská aplikácia používa pri správe klientov hlavičku X-Integrator-Token. Účastník a jeho oprávnenia sa spravujú cez Integrator API; samotné fakturačné volania potom používajú OAuth klienta a samostatný objekt Participant.

Správa účtov

X-Integrator-Token

Autorizuje bežné volania Integrator API.

Volania SAPI

OAuth client ID + secret

Klient získa Bearer token cez SAPI. Jeho secret príde iba pri vytvorení alebo rotácii.

Odoslanie PDS

X-PDS-Secret

Samostatné podpisové poverenie pre dávku PDS subjects.

Nastavenie: Laravel používa sekciu integrator_api a premenné EFAKTURA_INTEGRATOR_BASE_URL, EFAKTURA_INTEGRATOR_ID a EFAKTURA_INTEGRATOR_API_TOKEN. Bez Laravelu vytvorte klienta cez IntegratorAccountClientFactory. Použite URL a poverenia pre rovnaké prostredie.
Typický proces

Založte klienta, potom aktivujte jeho prístup.

Každý krok je samostatná operácia. Hostiteľ ukladá výsledky, secret store a stav onboardingu vo vlastnej aplikácii.

1VytvoreniecreateClient()POST klienta s hlavičkou X-Integrator-Token a stabilným Idempotency-Key.
2PovereniaUložte client ID a secretSecret z odpovede bezpečne uložte hneď; detail klienta ho neskôr nevráti.
3OprávneniaNastavte zoznam účastníkovreplaceClientParticipantAccess() nahrádza celý zoznam oprávnení klienta.
4AktiváciaVyžiadajte kontraktrequestParticipantActivation() s režimom SEND_ONLY alebo SEND_AND_RECEIVE.
5PrevádzkaVolajte SAPI a GatewayKlient získa OAuth token cez SAPI; Participant sa posiela pri konkrétnej operácii.
Rotácia secretu vráti novú jednorazovú hodnotu a automaticky sa neopakuje. Pri nejednoznačnom výsledku si stav overte pred ďalšou rotáciou. Poverenia integrátora, OAuth klienta a PDS nikdy nezapisujte do aplikačných logov.
Operácie

Štyri skupiny metód.

1. OAuth klienti

Správa klientov

listClients(), createClient(), getClient(), rotateClientSecret() a deleteClient(). Vytvorenie používa idempotency kľúč. Secret sa vracia iba pri vytvorení alebo rotácii.

2. Účastníci a prístupy

Participanti

listParticipants(), replaceClientParticipantAccess() a requestParticipantActivation(). Pri nahradení pošlite celý požadovaný zoznam; aktiváciu vytvorte s trvalým idempotency UUID.

3. Mesačný prehľad

Súhrn dokladov

getDocumentSummary() vracia počty dokladov pre mesiac vo formáte yyyyMM. Zoznamy klientov a účastníkov sa stránkujú pomocou pokračovacieho tokenu.

4. PDS subjects

Dávka PDS

submitPdsSubjects() odošle typovanú dávku a použije samostatné podpisové poverenie v X-PDS-Secret. Ide o oddelený tok; Integrator API token sa do PDS požiadavky neposiela.
